# Family Memories 动态改版执行思路

## 0. 已确认决策

- `/photos` 页面入口改名为 `/gallery`，旧 `/photos` 保留跳转兼容。
- 未登录状态只展示脱敏示例，不请求真实家庭私密数据。
- 时间线、年度回顾和近期记录使用真实数据库汇总查询。
- `paper`（温馨绘本）确认为默认主题。
- `AGENTS.md` 同步更新为家庭记忆主题化方向。

## 1. 背景判断

本次改版不应从零重做。当前项目已经从早期的个人成长记录站点，演进到“家庭私域记忆空间”的方向，并且代码里已经具备一部分基础能力：

- 技术栈已确定：Next.js App Router、React、Tailwind CSS、NextAuth、Prisma、PostgreSQL、Vercel Blob。
- 首页和登录页已经采用 `Family Memories · 成长记录` 的家庭记忆定位。
- 四套主题已经实现为 `paper`、`cinematic`、`playful`、`future`，分别对应温馨绘本、电影相册、绘本拼贴、清透相册。
- 主题选择已经支持 `localStorage` 保存，并且登录后通过 `/api/user/profile` 预留同步到用户资料。
- 已有内容页包括旅行、照片、生日视频、留言、个人资料、仪表盘。
- 现有数据模型支持用户、旅行记录、照片记录、生日视频、评论。

所以第一阶段的重点不是引入复杂后台，而是把已有雏形整理成更完整、更统一、更有产品感的家庭记忆系统。

## 2. 当前代码现状

关键文件：

- 首页：`app/page.tsx`
- 登录页：`app/login/page.tsx`
- 登录后首页：`app/dashboard/page.tsx`
- 旅行页：`app/travel/page.tsx`
- 生日视频页：`app/birthday/page.tsx`
- 摄影页：`app/gallery/page.tsx`
- 留言页：`app/messages/page.tsx`
- 主题定义：`lib/app-theme.ts`
- 主题 Provider：`components/providers/theme-provider.tsx`
- 通用主题外壳：`components/ui/theme-shell.tsx`
- 紧凑主题切换：`components/ui/compact-theme-selector.tsx`
- 数据模型：`prisma/schema.prisma`

已有能力：

- 首页已有 Hero、主题切换、隐私提示、三张模块卡片。
- Dashboard 与首页结构接近，但面向登录用户，已有“写日记”“上传照片”快捷入口。
- 内容页均在客户端判断登录态，未登录跳转 `/login`。
- 删除权限已有初步规则：作者或 admin 可删照片、留言，旅行页目前主要按作者控制。
- `User.role` 已存在，但只有粗粒度 `user/admin`，尚未形成家庭成员权限体系。

主要差距：

- 首页和 Dashboard 仍是三模块：旅行日记、摄影相册、生日影像；报告建议的六模块还未产品化。
- 路由命名已明确：摄影相册入口统一为 `/gallery`，旧 `/photos` 仅作为兼容跳转。
- 主题切换是常驻小组件，尚未实现首次访问轻量选择卡片。
- 首页缺少“近期记录”区域。
- 旅行页面目前是日记列表，还不是地图视图。
- 摄影页有分类和查看器雏形，但不是瀑布流/相册权限模型。
- 留言页是留言板，尚未做头像墙、置顶、私密回复、年度精选。
- 权限提示已在 UI 表达，但数据库和 API 层还没有邀请制、家庭成员、相册级权限。
- `AGENTS.md` 仍描述旧的“极简博客风格”，需要后续更新为当前家庭记忆主题化方向。

## 3. 产品目标

将 xiaomie.net 升级为：

一个面向家庭成员的私密成长记忆空间，用时间线、影像、旅行、相册、留言和年度回顾，持续沉淀家庭生活。

核心关键词：

- 私密
- 温暖
- 长期记录
- 家庭共创
- 主题化
- 可回看

本轮建议优先实现“产品外壳和信息架构完整”，暂不优先做复杂权限后台。

## 4. 第一阶段范围

第一阶段目标：让网站从“三入口展示页”升级为“六模块家庭记忆系统首页”。

建议完成：

- 首页改为六模块入口：成长时间线、生日影像、旅行地图、摄影相册、家庭留言、年度回顾。
- Dashboard 同步改为六模块入口，但保留登录后的快捷操作。
- 统一导航：成长时间线、生日影像、旅行地图、摄影相册、家庭留言、年度回顾、登录/个人入口。
- 主题系统保留现有实现，补齐首次访问主题选择。
- 新增 `/timeline`、`/gallery`、`/year-review`、`/settings/theme` 路由。
- `/gallery` 第一阶段复用当前照片能力，避免重复开发。
- `/travel` 第一阶段先命名和视觉升级为“旅行地图”，地图能力可先用静态地点列表和路线视觉占位，不急着接真实地图 SDK。
- 首页增加“近期记录”区域，先用现有 API 数据或静态 fallback。
- 登录页保留“家人专属入口”，强化邀请制和权限说明，但不在第一阶段强制引入邀请码注册。

第一阶段不建议做：

- 完整家庭成员管理后台。
- 相册级权限数据库重构。
- 自动年度报告生成。
- 语音留言、复杂私密回复。
- 地图 SDK 和路线回放的完整接入。
- Framer Motion 依赖引入，除非讨论后确认需要。当前 CSS transition 与 Tailwind 已够支撑轻量动态。

## 6. 首页改造思路

首页结构建议：

1. 顶部导航
   - 未登录：六模块入口均可展示，但点击内容页跳转登录。
   - 已登录：显示个人入口和退出/资料入口。

2. Hero
   - 主标题：把每一个平凡的日子，封存为家的记忆胶囊
   - 副标题：记录成长、珍藏影像、保存足迹，也留下家人之间最温暖的话。
   - 主按钮：开始记录
   - 次按钮：选择主题
   - 隐私提示：邀请制访问 · 相册权限 · 仅家人可见

3. 六模块入口
   - 成长时间线：按年月、年龄、重要节点查看成长故事。
   - 生日影像：按年份归档生日视频、照片和祝福。
   - 旅行地图：聚合城市、路线、旅行日记和照片。
   - 摄影相册：日常、旅行、生日、节日、精选相册。
   - 家庭留言：家人祝福、心里话、生日专题留言。
   - 年度回顾：年度关键词、照片数、视频数、旅行城市数。

4. 近期记录
   - 未登录：展示脱敏的示例记录或最近记录摘要。
   - 已登录：展示真实最近照片、旅行、留言、生日视频。

5. 主题选择
   - 当前紧凑主题选择器可以保留，但入口位置应从内容流中上移到 Header 或 Hero CTA 附近。
   - 首次访问弹出轻量选择卡片，用户选择后写入 `localStorage`。

6. 页脚
   - Family Memories · 成长记录 Since 2014

## 7. 四套主题策略

当前主题 token 已基本符合报告方向，建议保留命名但在 UI 文案中使用中文名：

- `paper`：温馨绘本，默认主题。
- `cinematic`：电影相册。
- `playful`：绘本拼贴。
- `future`：清透相册。

需要注意：

- `prisma/schema.prisma` 中 `User.theme` 默认值应保持为 `paper`，并通过迁移同步数据库默认值。
- `theme-provider.tsx` 当前已经用 `theme-style-version` 强制旧样式重置为 `paper`，这与默认主题方向一致。
- `appThemeStyles` 里已有大量 Tailwind class token，可以继续扩展，不需要另起一套主题系统。
- 对新增页面要统一使用 `ThemedShell`、`ThemedHeader`、`ThemedPageHero`、`useCurrentThemeStyle`，减少样式分叉。

## 8. 内容页第一阶段落地方式

### 成长时间线 `/timeline`

第一阶段可以先做静态/聚合视图：

- 顶部年份筛选。
- 时间线节点卡片。
- 节点类型：生日、旅行、照片、留言、成长事件。
- 数据可先从生日视频、旅行、照片中聚合，缺失的成长事件用本地 mock 占位。

后续再新增独立 `TimelineEntry` 数据模型。

### 生日影像 `/birthday`

保留当前生日视频能力，视觉升级：

- 年份卡片。
- 视频封面。
- 生日描述。
- 预留祝福留言和生成生日回顾入口。

短期不需要真实 3 秒 hover 预览，B 站视频封面和播放弹窗优先。

### 旅行地图 `/travel`

保留当前旅行日记数据，视觉升级为“地图感”：

- 左侧/顶部旅行列表。
- 右侧/主体为地点卡片或轻量地图插画占位。
- 旅行记录继续使用 `TravelEntry.location`、`travelDate`、`coverImage`。

真实地图 SDK 放到第二阶段。

### 摄影相册 `/gallery`

基于当前 `/photos`：

- 新增 `/gallery` 页面，复用照片列表能力。
- 分类从当前 `风景/人物/生活/旅行` 调整为 `全部/日常/旅行/生日/节日/精选`。
- 网格优先，瀑布流可以第二阶段再做。
- 图片查看器保留，补充下载/收藏/设为封面可以先只做 UI 预留。

### 家庭留言 `/messages`

基于当前留言板：

- 标题和文案改为“家庭留言”。
- 卡片视觉更像祝福卡片。
- 保留发送、删除、作者头像。
- 置顶、私密回复、语音留言放到后续。

### 年度回顾 `/year-review`

第一阶段新建展示页：

- 年度封面。
- 统计卡：照片数、生日视频数、留言数、旅行记录数。
- 月度回顾卡片。
- 年度精选入口。

统计可从现有 API 或服务端查询聚合；如果短期不接服务端，可先用前端 mock + 预留接口。

## 9. 权限与隐私策略

第一阶段目标是“表达清楚、入口受控、数据不外泄”。

已有做法：

- 多数内容页客户端检查 `useSession`，未登录跳转 `/login`。
- API 层通过 `getServerSession` 做基础认证。
- 用户有 `role` 字段。

建议第一阶段补强：

- 给所有内容页统一登录保护体验，避免每个页面重复实现时行为不一致。
- API 层继续坚持服务端认证，不依赖前端跳转作为唯一保护。
- 首页只展示介绍和入口，不直接暴露完整照片、视频、留言正文。
- 登录页继续强调邀请制访问、相册权限、仅家人可见。

第二/三阶段再做：

- 邀请码注册。
- 家庭成员身份模型。
- 访客、受邀家人、核心家人、管理员权限层级。
- 相册级权限。
- 单条内容私密设置。
- 儿童照片默认不公开。

## 11. 分期计划

目标：让公开首页、登录页、Dashboard 和六模块入口完整成型。

任务：

- 改造首页为六模块。
- 改造 Dashboard 为六模块。
- 新增 `/timeline`、`/gallery`、`/year-review`、`/settings/theme` 页面雏形。
- 新增首次访问主题选择。
- 增加近期记录区域。
- 保持四主题切换、刷新保留、登录同步。
- 更新项目说明文档中的设计方向。

验收：

- 首页展示六个模块。
- 四套主题可切换。
- 刷新后主题保留。

### 第二期：内容页增强

目标：让六个模块各自具备可浏览的真实页面体验。

任务：

- 时间线聚合生日、旅行、照片。
- 旅行页升级地图式布局。

- 留言页升级祝福墙视觉。
- 年度回顾接入统计数据。
- 增强空状态和加载状态。

验收：

- 每个模块都有完整页面。
- 有数据时展示真实内容，无数据时展示明确空状态。
- 页面视觉在四主题下都保持可读。

### 第三期：真实权限和家庭共创

目标：把“邀请制访问、相册权限、仅家人可见”从 UI 表达变成真实产品能力。

任务：

- 邀请码注册。
- 家庭成员模型。

- 相册和内容可见范围。

- 未授权用户无法通过页面或 API 读取私密内容。

- 普通家人只能访问授权内容。

## 12. 风险与取舍

- 不建议第一期引入地图 SDK。地图依赖、样式、移动端适配和隐私问题都会扩大工作量。
- 不建议第一期做复杂权限表。当前核心是建立产品感和信息架构，权限模型应等页面边界稳定后再落库。
- 不建议引入 Framer Motion 作为第一期必要依赖。现有 Tailwind transition 足够支撑轻量动态。
- 需要注意主题色不要让页面变成单色堆叠，尤其是电影相册和清透相册主题下，卡片层级和文字对比要逐页检查。
- 首页与 Dashboard 目前重复较多，第一期应顺手抽配置和卡片组件，否则六模块改造会扩大重复代码。

## 13. 建议讨论点

在开始实施前，建议先确认以下问题：

1. `/photos` 是否直接改名为 `/gallery`，还是保留 `/photos` 并新增 `/gallery` 兼容入口。
2. 首页未登录状态是否允许展示真实最近记录摘要，还是全部使用脱敏示例。
3. 第一阶段的 `/timeline` 和 `/year-review` 是否接受 mock/聚合数据，还是必须接真实数据库查询。
4. 是否把 `paper` 确认为所有新用户默认主题。
5. 是否同步更新 `AGENTS.md`，把旧的极简博客风格改成家庭记忆主题化设计规范。
